# Задача 4. LRUMemo — 9/10

Расчёт цены занимает много времени, а запросы повторяются. Напишите
декоратор, который запоминает результаты и хранит не больше `capacity`
записей. При переполнении удаляется запись, к которой дольше всего
не обращались: это политика **LRU**, Least Recently Used.

Реализуйте класс-декоратор `LRUMemo` в `lru_memo.py`.

```python
class LRUMemo:
    def __init__(self, capacity: int) -> None: ...
    def __call__[**P, R](self, func: Callable[P, R]) -> Cached[P, R]: ...
```

`Cached` уже описывает интерфейс возвращаемой обёртки. Его менять не нужно.
Обёртка остаётся обычной функцией с дополнительными атрибутами и операциями.

## Когда вызовы одинаковы

```python
def price(product: int, currency: str = "RUB") -> object: ...
```

Для кэша все следующие вызовы одинаковы:

```python
price(10)
price(product=10)
price(10, "RUB")
price(currency="RUB", product=10)
```

- Вызовы считаются одинаковыми, если значения соответствующих параметров
  равны. Способ передачи аргументов и явная передача значения по умолчанию
  на это не влияют. Поддерживаются все виды параметров: обычные, только
  позиционные (`/`), только именованные (`*`), `*args` и `**kwargs`.
- Порядок передачи именованных аргументов не влияет на ключ, в том числе
  внутри `**kwargs`. При этом отдельные параметры, `*args` и `**kwargs`
  не смешиваются: учитывается, к какому параметру относится значение.
- Значения аргументов, включая значения по умолчанию, должны быть
  хешируемыми. Нехешируемое значение вызывает `TypeError` **до** вызова
  функции и изменения статистики. Это требование относится к отдельным
  значениям, переданным через `**kwargs`, а не к самому словарю параметров.
- Ключи используют обычные правила равенства и хеширования Python:
  отдельного различения равных значений разных типов не требуется.
  Хеш и равенство переданных объектов не меняются во время хранения.
- Разные значения аргументов с совпадающими хешами не считаются равными.

## Работа кэша и статистика

- `capacity` — положительное целое число. При `capacity < 1` конструктор
  сразу вызывает `ValueError`. Создание объекта и декорирование функцию
  не запускают. Поддерживаются обычные функции с доступной сигнатурой.
- При попадании верните сохранённый объект без вызова исходной функции,
  увеличьте `hits` и сделайте запись самой недавно использованной.
- При промахе увеличьте `misses` и вызовите функцию. Успешный результат
  сохраните как самый свежий. `None` и ложные значения — полноценные ответы.
- При переполнении удалите самую давно использованную запись. Здесь
  учитываются **обращения**, а не только добавления: LRU отличается от FIFO.
- Если функция возбуждает исключение, промах засчитывается, исключение
  проходит наружу без замены. Результат не сохраняется; существующие записи
  и порядок их использования не меняются из-за этой неудачи.
- Неверный набор аргументов вызывает `TypeError` без выполнения функции,
  изменения кэша и счётчиков.
- `hits: int` и `misses: int` изначально равны нулю.
  `cache_size() -> int` возвращает текущее число записей;
  `cache_clear() -> None` очищает кэш и обнуляет оба счётчика.
- Один объект `LRUMemo` можно применять к нескольким функциям. У каждой
  обёртки свой кэш и своя статистика; очистка одной не влияет на другие.
- Метаданные сохраняются по [общим требованиям](../../README.md#общие-требования).
  Исходная сигнатура должна быть доступна через `inspect.signature`.

Поиск записи, изменение порядка обращений и вытеснение должны занимать
`O(1)` в среднем. Построение и хеширование ключа, а также выполнение функции
в эту оценку не входят. Готовые `functools.cache` и `functools.lru_cache`
использовать нельзя.

```python
calls = []


@LRUMemo(capacity=2)
def price(product: int, *, currency: str = "RUB") -> tuple[int, str]:
    calls.append(product)
    return product, currency


first = price(10)
price(product=10, currency="RUB") is first  # True — попадание
price(20)
price(10)  # попадание: 10 теперь свежее 20
price(30)  # вытесняется 20
price(20)  # промах: нужно вычислить снова

calls  # [10, 20, 30, 20]
price.hits  # 2
price.misses  # 4
price.cache_size()  # 2
price.cache_clear()
price.cache_size()  # 0
price.hits  # 0
```

`cache_clear()` вызывают между вызовами функции. Рекурсивные вызовы через
ту же обёртку не рассматриваются.
