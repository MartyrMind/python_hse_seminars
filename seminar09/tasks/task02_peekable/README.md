# Задача 2. peekable — 6/10

Парсеру нужно посмотреть на следующий токен, прежде чем решить, как его
обработать. Обычный `next()` уже расходует токен. Напишите обёртку, которая
может сохранить один прочитанный элемент и показать его несколько раз.

Реализуйте обобщённый класс `Peekable[T]` в файле `peekable.py`.

- `Peekable(source: Iterable[T])` получает итератор источника один раз, но
  пока не запрашивает его элементы. Обёртка сама является итератором.
- `__iter__() -> Self` возвращает `self`.
- `peek() -> T` возвращает следующий элемент, сохраняя его для `next()`.
  Повторные `peek()` показывают тот же элемент без новых запросов к источнику.
- `__next__() -> T` возвращает сохранённый элемент, если он есть; иначе
  запрашивает следующий у источника.
- Когда источник завершился, `peek()` и `next()` вызывают `StopIteration`.
  После первого обнаруженного конца больше не обращайтесь к источнику.
- Другие исключения проходят наружу без замены. Такая ошибка сама по себе
  не завершает обёртку: следующий вызов может снова обратиться к источнику.
- `None` и любые ложные значения допустимы. Дополнительная память — `O(1)`:
  храните максимум один прочитанный элемент, не копируйте весь источник.

```python
walk = Peekable(iter([None, 10, 20]))
iter(walk) is walk             # True
walk.peek()                    # None
walk.peek()                    # None
next(walk)                     # None
next(walk)                     # 10
walk.peek()                    # 20
list(walk)                     # [20]
walk.peek()                    # StopIteration
```

`peek()` не расходует элемент **для пользователя обёртки**, но первый такой
вызов физически читает элемент исходного итератора. Если обращаться к исходному
итератору отдельно, это чтение будет заметно. Тесты проверяют именно число и
момент реальных запросов, а не устройство ваших полей.
