# Задача 3. call_iterator — 7/10

Датчик отдаёт показания по вызову функции. Одно специальное значение означает
конец измерений. Нужно превратить такой источник в итератор, чтобы с ним
работали `next()`, `for` и другие обычные потребители итераторов.

Реализуйте класс `CallIterator[T]` в файле `call_iterator.py`. Он моделирует
вторую форму встроенного `iter(callable, sentinel)`, но механизм нужно написать
самостоятельно: **готовую двухаргументную форму `iter` использовать нельзя**.

- `CallIterator(source: Callable[[], T], sentinel: object)` сохраняет источник
  и сигнал, но не вызывает источник. Считайте, что `source` вызываем.
- `__iter__() -> Self` возвращает `self`.
- `__next__() -> T` вызывает `source()` **без аргументов** один раз.
- Если результат равен сигналу через `==`, вызов завершает итератор через
  `StopIteration`. Сам сигнал не выдаётся.
- Если `source()` сам вызывает `StopIteration`, это тоже окончательное
  завершение. После обнаруженного конца больше не вызывайте источник.
- Остальные исключения источника или сравнения проходят наружу без замены.
  Они не означают окончательного завершения: новый `next()` может повторить
  попытку, вызвав источник заново. Прочитанное при ошибке сравнения значение
  повторно не используется.
- Сравнивайте сигнал через `==`, а не `is`; например, `0 == 0.0`.
  `None` может быть обычным показанием, если сигналом выбрано другое значение.
- Храните только источник, сигнал и состояние окончания: память `O(1)`.

```python
readings = iter([10, None, 20, "STOP", 99])
walk = CallIterator(lambda: next(readings), "STOP")

next(walk)                     # 10
list(walk)                     # [None, 20]
next(walk)                     # StopIteration
next(readings)                 # 99 — после сигнала источник не трогали
```

Функция с аргументами тоже может стать источником: `partial(read, 3)` из
`functools` создаёт вызываемый объект без обязательных аргументов. В этой
задаче вы пишете универсальный итератор; функцию чтения файла писать не нужно.
