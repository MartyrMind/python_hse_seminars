# Задача 6. relay — 9/10

Система добавляет отметки о начале и завершении работы стороннего генератора.
При этом его пользователь должен по-прежнему получать значения, передавать
ответы и исключения и закрывать работу. Простая передача элементов циклом
`for` сохраняет значения, но не весь этот интерфейс.

Реализуйте в файле `relay.py` обобщённую генераторную функцию
`relay[Y, S, R](worker: Generator[Y, S, R], events: list[str]) -> Generator[Y, S, R]`.
`worker` — уже созданный, ещё не запущенный настоящий генератор. Другие типы
объектов и предварительно запущенные генераторы поддерживать не требуется.

- Вызов `relay` ничего не выполняет: оба генератора пока не запущены,
  `events` не меняется.
- Первый запрос результата добавляет `"started"` и начинает `worker`.
- Используйте **`yield from`**, чтобы делегировать выдачу значений,
  `send(value)`, `throw(exception)` и закрытие.
- Если `worker` обработал исключение и выдал очередное значение, его должен
  вернуть вызов `throw` на внешнем генераторе. Обёртка продолжает работать.
- Необработанное исключение выходит наружу без замены.
- При нормальном завершении верните результат `worker` как результат внешнего
  генератора. Это не очередной выдаваемый элемент.
- В `finally` запишите `"finished"` ровно один раз при любом завершении
  **запущенной** обёртки: обычном, из-за ошибки или через `close()`.
- Закрытие активной обёртки закрывает и вложенный генератор: его `finally`
  выполняется раньше записи внешнего `"finished"`.
- Закрытие ещё не запущенной обёртки не запускает её тело, не меняет `events`
  и не запускает/не закрывает `worker`. Это обычная семантика генераторов.

В `Generator[Y, S, R]` параметры обозначают тип выдаваемых значений, тип
принимаемых через `send` ответов и тип результата `return` соответственно.
Сохраните эту связь типов в сигнатуре.

```python
def worker():
    answer = yield "Сколько?"
    yield answer * 2
    return "готово"

events = []
walk = relay(worker(), events)
next(walk)                  # "Сколько?"
walk.send(7)                # 14
events                      # ["started"]
next(walk)                  # StopIteration, у исключения value == "готово"
events                      # ["started", "finished"]
```

Результат `return` можно получить, перехватив `StopIteration` и прочитав
`exception.value`. Обычный `for` завершает обход, не выдавая этот результат.
`yield from` позволяет получить его как значение выражения делегирования.

Другие задачи не импортируйте: тесты передают собственные генераторы.
