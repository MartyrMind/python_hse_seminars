# Задача 1. buckets — 5/10

В журнале события разложены по категориям. Запись в новую категорию должна
создавать список, но просмотр неизвестной категории не должен оставлять
в журнале пустую запись. Пользователь может менять полученный список,
не удаляя события из самого журнала.

Реализуйте `Buckets[T]` в файле `buckets.py`, используя `defaultdict(list)`.

- Конструктор создаёт пустое хранилище. Экземпляры независимы.
- `add(key: str, value: T) -> None` добавляет объект в конец списка категории.
  Списки разных категорий независимы. Пустая строка — допустимый ключ.
- `peek(key: str) -> list[T]` возвращает **новый список** значений категории.
  Для неизвестного ключа возвращает новый пустой список, не создавая категорию.
- `keys() -> list[str]` возвращает новый список категорий в порядке первого
  добавления. Последующие добавления порядок не меняют.
- Копируется только внешний список: значения внутри остаются теми же объектами.
  `None` и ложные значения не имеют специального смысла.
- Добавление — амортизированное `O(1)`, просмотр — `O(m)` для категории из
  `m` элементов, список ключей — `O(k)` для `k` категорий.

```python
journal = Buckets[int]()
journal.peek("ошибки")          # []
journal.keys()                  # [] — просмотр ничего не создал
journal.add("ошибки", 500)
journal.add("запросы", 200)
journal.add("ошибки", 404)
journal.peek("ошибки")          # [500, 404]
journal.keys()                  # ["ошибки", "запросы"]

snapshot = journal.peek("ошибки")
snapshot.clear()
journal.peek("ошибки")          # [500, 404]
```

Для добавления подходит обращение `storage[key]`. Для просмотра подумайте,
чем `storage.get(key)` отличается от такого обращения. Фабрика `list`
должна создавать новый список, а не возвращать один заранее созданный.
