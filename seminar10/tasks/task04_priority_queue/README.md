# Задача 4. priority_queue — 7/10

Диспетчер запускает задания с меньшим числом приоритета раньше остальных.
Если приоритеты совпали, задания запускаются в порядке поступления. Сами
задания могут быть словарями или произвольными объектами, которые нельзя
сравнивать между собой.

Реализуйте `PriorityQueue[T]` в файле `priority_queue.py`, используя `heapq`.

- Конструктор создаёт пустую очередь. Экземпляры независимы.
- `push(priority: int, item: T) -> None` добавляет объект с целочисленным
  приоритетом. Допустимы отрицательные приоритеты и повторные добавления.
- `peek() -> T` возвращает следующее задание, сохраняя его в очереди.
- `pop() -> T` извлекает следующее задание.
- `__len__() -> int` возвращает число оставшихся заданий.
- Среди равных приоритетов раньше выдаётся раньше добавленный объект,
  в том числе после чередования добавлений и извлечений.
- Значения заданий не копируются и **вообще не сравниваются** между собой.
  `None` и ложные значения — обычные задания.
- `peek()` и `pop()` пустой очереди вызывают `IndexError`. После ошибки
  очередью можно продолжать пользоваться; текст исключения не важен.
- Добавление и извлечение — `O(log n)`, просмотр и длина — `O(1)`.
  Сортировать всю очередь при каждом вызове нельзя.

```python
queue = PriorityQueue[str]()
queue.push(5, "первое обычное")
queue.push(1, "срочное")
queue.push(5, "второе обычное")
queue.peek()                    # "срочное"
len(queue)                      # 3
queue.pop()                     # "срочное"
queue.pop()                     # "первое обычное"
queue.pop()                     # "второе обычное"
```

Кортежи сравниваются по полям слева направо. Пары `(priority, item)` опасны:
при равном приоритете сравнение дойдёт до `item`. Добавьте между полями
уникальный возрастающий номер поступления; для этого подходит `itertools.count`.
В вершине кучи находится минимум, но остальная куча не обязана быть отсортирована.
