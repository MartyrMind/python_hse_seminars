# Задача 2. window_counts — 6/10

Мониторинг показывает частоты событий только за последние `width` записей.
Когда приходит новая запись, старая может выйти из окна. Пересчитывать
всё окно с нуля после каждого события не нужно.

Реализуйте генератор
`window_counts(source: Iterable[str], width: int) -> Iterator[dict[str, int]]`
в файле `window_counts.py`. Используйте `deque` для порядка событий и
`Counter` для текущих частот.

- После каждого прочитанного события выдайте частоты последних **не более
  `width`** событий. Пока окно не заполнено, считайте все полученные события.
- Каждый ответ — новый обычный `dict`. В нём только положительные частоты:
  ключ с частотой ноль удаляется. Порядок ключей ответа не важен.
- Изменение ответа не влияет на следующие ответы; новые события не меняют
  уже выданные словари.
- При вызове функции источник не запускается. На каждый ответ читается
  ровно одно новое событие, без чтения наперёд. Источник может быть одноразовым
  или бесконечным. Пустой источник не даёт ответов; пустая строка допустима.
- При `width <= 0` первый запрос результата вызывает `ValueError` до
  получения итератора источника. Другие ошибки источника проходят наружу.
- На обновление очереди и счётчика — `O(1)` в среднем; создание ответа —
  `O(d)`, где `d` — число разных событий в текущем окне. Рабочая память —
  `O(width)`, без учёта сохранённых потребителем ответов.

```python
list(window_counts(["a", "b", "a", "c"], 2))
# [{"a": 1}, {"a": 1, "b": 1}, {"a": 1, "b": 1}, {"a": 1, "c": 1}]

source = iter(["x", "y", "z"])
walk = window_counts(source, 2)
next(walk)                      # {"x": 1}
next(source)                    # "y" — генератор не читал наперёд
```

Если у `deque` установлен `maxlen`, старый элемент исчезает автоматически.
Для обновления счётчика нужно успеть узнать, какой именно элемент уходит.
Можно вместо этого управлять удалением самостоятельно через `popleft()`.
При уменьшении частоты `Counter` сам не удаляет нулевой ключ.
