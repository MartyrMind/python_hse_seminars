# Задача 5. task_queue — 9/10

Реализуйте очередь вызовов функций. Вызовы выполняются позже, причём результат
одного можно передать в аргументы следующего ещё до запуска очереди.

## Интерфейс

```python
class Result:
    def __init__(self): ...


class TaskQueue:
    def __init__(self): ...
    def submit(self, func, /, *args, **kwargs): ...
    def run_all(self): ...
```

`submit` добавляет вызов в очередь и возвращает новый объект `Result`.
У него два поля: `ready` изначально равно `False`, `value` — `None`.
Сразу после выполнения вызова `ready` становится `True`, а `value` содержит
результат функции. Результат `None` тоже считается готовым.

## Требования

- Каждая очередь изначально пуста и работает независимо от других.
- `submit` ничего не вызывает. У каждого добавленного вызова свой `Result`.
- `run_all` выполняет вызовы в порядке добавления, каждый ровно один раз,
  и возвращает новый список результатов. Результаты `None` тоже входят в список.
- Если аргумент — объект `Result`, перед вызовом вместо него передаётся
  его `value`. Это правило действует для позиционных и именованных аргументов.
  Подстановка выполняется один раз; внутрь списков и словарей заглядывать не нужно.
  Если `value` тоже является `Result`, передаётся этот объект без дальнейшей подстановки.
- Функции, экземпляры связанных методов и обычные аргументы не копируются.
  Поле `value` и список, возвращённый `run_all`, содержат исходные результаты функций.
- Выполненные вызовы удаляются из очереди. Для пустой очереди результат — `[]`.
- Вызовы, добавленные во время выполнения, остаются до следующего `run_all`.
  Их объекты `Result` пока остаются неготовыми.
- Результат выполненного вызова можно использовать и при следующем запуске очереди.

Все вызовы корректны и завершаются успешно. В аргументах встречаются только
результаты вызовов, добавленных в эту же очередь **раньше**; циклических
зависимостей нет. К моменту использования такой результат уже готов.
Объекты `Result` внутри контейнеров в аргументах не встречаются.

Пользовательский код читает `ready` и `value`, но не присваивает им значения.
Выполняемая функция может делать `submit`, но не вызывает `run_all` и не меняет
внутренние поля очереди напрямую.

## Обязательные приёмы

Используйте обычные классы с `__init__`, полями и методами. Сохраните сигнатуры.
Храните функции и аргументы как объекты Python; при вызове используйте распаковку.
Готовые библиотечные очереди, `eval`, `exec` и `deepcopy` использовать нельзя.

## Примеры

```python
queue = TaskQueue()
items = []
added = queue.submit(items.append, 7)
length = queue.submit(len, items)
text = queue.submit(str, length)

items  # []
length.ready  # False
length.value  # None

queue.run_all()  # [None, 1, "1"]
added.ready  # True
added.value  # None
text.value  # "1"
queue.run_all()  # []
```

Один результат может быть использован несколько раз:

```python
def add(x, *, y):
    return x + y


number = queue.submit(int, "7")
total = queue.submit(add, number, y=number)
queue.run_all()  # [7, 14]
total.value  # 14
```

Вызов, добавленный во время выполнения, ждёт следующего запуска:

```python
def schedule():
    queue.submit(str, total)
    return "запланировано"


scheduled = queue.submit(schedule)
queue.run_all()  # ["запланировано"]
queue.run_all()  # ["14"]
```
