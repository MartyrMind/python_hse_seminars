# Задача 5. AtomicExport — 9/10

Склад регулярно пересобирает текстовый отчёт. Пока новый отчёт пишется,
читатели должны видеть прежнюю полную версию. Неудачную попытку можно пропустить,
если ошибка относится к заранее разрешённым и общий лимит пропусков ещё не
исчерпан. Пропущенные ошибки нужно сохранить для разбора.

Реализуйте класс `AtomicExport(target: Path, *, allowed: tuple[type[Exception],
...] = (), limit: int = 0)`. Его используют как контекстный менеджер:

```python
export = AtomicExport(path, allowed=(ValueError,), limit=2)

with export as report:
    report.write("ручка;2\n")
```

В заготовке дана готовая функция `make_temp(target) -> (temp_path, stream)`. Она
создаёт временный текстовый файл в каталоге `target`, открывает его в UTF-8 и
возвращает путь и поток. Используйте её в `__enter__`; реализовывать фабрику не
нужно. Это также позволяет тестам воспроизвести ошибку закрытия файла.

## Контракт

- `target` — путь будущего отчёта типа `Path`. Его родительский каталог
  существует. `limit` неотрицателен; при отрицательном значении конструктор
  поднимает `ValueError`. Типы в `allowed` — подклассы `Exception`.
- Один объект можно использовать в нескольких **последовательных** блоках
  `with`. Каждый вход создаёт новый временный файл. Бюджет общий для всех
  попыток и не сбрасывается после успеха.
- `__enter__` возвращает открытый поток. До успешного выхода из блока целевой
  файл не меняется. Если `make_temp` поднимает исключение, оно выходит наружу;
  функция по контракту не оставляет после такой ошибки временных файлов.
- При успешном завершении тела `__exit__` закрывает поток и заменяет целевой
  файл через `os.replace(temp_path, target)`. После этого временного файла нет.
- Если тело блока подняло допустимое исключение и `len(errors) < limit`,
  `__exit__` закрывает и удаляет временный файл, добавляет **тот же объект**
  исключения в публичный список `errors` и подавляет его. Иначе временный файл
  тоже удаляется, а исходное исключение выходит наружу без замены. В `errors`
  попадают только подавленные ошибки тела блока.
- `KeyboardInterrupt` и `SystemExit` никогда не подавляются.
- Если `close()` поднимает исключение при успешном теле блока, удалите временный
  файл и пропустите ошибку закрытия наружу без замены. Если упали и тело, и
  `close()`, поднимите группу с **обоими исходными объектами** в порядке
  «ошибка тела, ошибка закрытия». Для двух обычных `Exception` это
  `ExceptionGroup`; если хотя бы один объект не является `Exception`, это
  `BaseExceptionGroup`. Такой двойной сбой не расходует бюджет и не
  добавляется в `errors`.
- Если `os.replace` поднимает исключение, удалите временный файл и пропустите
  ошибку замены наружу без обёртки. Она также не расходует бюджет.
- Удаление временного файла по контракту всегда успешно. Гарантию сохранности
  файла после отключения питания в этой задаче не рассматриваем.

Например, после разрешённой ошибки прежний отчёт остаётся на месте:

```python
export = AtomicExport(path, allowed=(ValueError,), limit=1)

with export as report:
    report.write("неполный отчёт")
    raise ValueError("строка повреждена")  # подавлено, файл не опубликован

assert len(export.errors) == 1
```
