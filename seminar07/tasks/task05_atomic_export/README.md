# Задача 5. AtomicExport — 9/10

Склад регулярно пересобирает текстовый отчёт. Пока новый отчёт пишется,
читатели должны видеть прежнюю полную версию. Неудачную попытку можно пропустить,
если ошибка относится к заранее разрешённым и общий лимит пропусков ещё не
исчерпан. Пропущенные ошибки нужно сохранить для разбора.

Реализуйте класс `AtomicExport(target: Path, *, allowed: tuple[type[Exception],
...] = (), limit: int = 0)`. Его используют как контекстный менеджер:

```python
export = AtomicExport(path, allowed=(ValueError,), limit=2)

with export as report:
    report.write("ручка;2\n")
```

В заготовке уже есть `make_temp(target) -> (temp_path, stream)`: она создаёт
временный текстовый файл рядом с целевым и возвращает его путь и открытый
поток. Используйте эту функцию; реализовывать её не требуется.

## Контракт

- `target` — путь будущего отчёта типа `Path`. Его родительский каталог
  существует. `limit` неотрицателен; при отрицательном значении конструктор
  поднимает `ValueError`. Типы в `allowed` — подклассы `Exception`.
- При входе в `with` возвращается открытый текстовый поток. Пока блок
  выполняется, целевой файл не меняется. Один объект `AtomicExport` можно
  использовать в нескольких **последовательных** блоках; для каждой попытки
  нужен новый временный файл.
- Если блок завершился успешно, поток закрывается и новый отчёт заменяет
  прежний. Для публикации используется `os.replace`. Временного файла после
  выхода из блока не остаётся.
- Если блок завершился исключением, прежний отчёт остаётся на месте. Ошибка
  подавляется только тогда, когда она подходит под `allowed` и число уже
  подавленных ошибок меньше `limit`. В этом случае тот же объект исключения
  добавляется в публичный список `errors`. В остальных случаях исключение
  выходит наружу без замены. Поток закрывается и после ошибки блока; в `errors`
  попадают только подавленные ошибки тела блока. Бюджет общий для всех попыток
  и после успеха не сбрасывается; `KeyboardInterrupt` и `SystemExit` не
  подавляются.
- Если закрытие временного файла тоже завершилось ошибкой, отчёт не
  публикуется. При успешном блоке наружу выходит ошибка закрытия. При ошибке
  блока поднимается группа с обоими исходными исключениями в порядке «ошибка
  блока, ошибка закрытия»: `ExceptionGroup` для двух обычных `Exception` и
  `BaseExceptionGroup`, если хотя бы одна ошибка не является `Exception`.
- Если публикация завершилась ошибкой, прежний отчёт остаётся на месте, а сама
  ошибка выходит наружу без обёртки. Ошибки закрытия и публикации не расходуют
  бюджет и не добавляются в `errors`.
- После неудачной попытки временного файла не остаётся. Ошибка создания
  временного файла также выходит наружу и не меняет целевой файл. Удаление
  временного файла по контракту успешно; сохранность после отключения питания
  в задаче не рассматривается.

Например, после разрешённой ошибки прежний отчёт остаётся на месте:

```python
export = AtomicExport(path, allowed=(ValueError,), limit=1)

with export as report:
    report.write("неполный отчёт")
    raise ValueError("строка повреждена")  # подавлено, файл не опубликован

assert len(export.errors) == 1
```

## Подсказки

Могут пригодиться `os.replace`, `Path.unlink`, `ExceptionGroup` и
`BaseExceptionGroup`. Для создания временного файла используйте готовую
`make_temp`.
